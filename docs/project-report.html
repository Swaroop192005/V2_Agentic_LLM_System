Final-Year Project · Technical Report

An Agentic Multi-LLM Answer-Validation System

A pipeline that generates answers from two language models, evaluates them with two more under a bias-controlled protocol, corroborates against external knowledge, and gates its own output on a statistically calibrated confidence score — built and validated end-to-end over a 5,000-question run.

Status Data collection complete Dataset 5,000 questions · 8,432 attempts Judge qwen3.5:9b Verifier phi3 Generators LLaMA 3 · Mistral
01 · Abstract

What was built, and what was found

This project builds a six-stage agentic pipeline that answers open-ended technical questions and validates the answer without any human-labelled ground truth. Two independent models generate candidate answers; two further models score them on a shared eight-factor rubric; three external checks corroborate the winner; and a weighted confidence score decides whether the answer ships or is regenerated.

The central research problem is that none of the usual quality metrics apply: there is no "correct answer" label anywhere in the data, so every design choice — which judge model, what rubric, which signals, what confidence threshold — had to be justified by internal, label-free evidence rather than accuracy against a target. The project's real contribution is the method for doing that credibly, and a running record of catching its own measurement errors before they became conclusions.

The completed dataset spans 5,000 questions under one consistent, bias-corrected regime. Key results: a judge model selected on per-criterion discrimination (not just score averages); position and model-identity bias identified and eliminated; and a regeneration threshold of 0.75 that three independent statistical methods agree is well-calibrated.

02 · Problem statement

Validating answers when there is no answer key

A single language model, asked a hard question, will produce a fluent answer whether or not it is correct — and it cannot reliably tell you which. That is the gap this project addresses.

The naive fix — have a second model "check" the first — fails quietly, because a checker model shares the same failure modes and biases as the generator, and tends to rubber-stamp plausible-sounding text. Any system built this way needs to answer three uncomfortable questions:

  • How do you know the judge is any good? An LLM judge that scores every answer 76/80 is useless, no matter how confident it sounds.
  • How do you know the scores measure quality, not artefacts? Position on the page, apparent verbosity, or which brand wrote an answer can all leak into a score and masquerade as quality.
  • How do you set a "good enough" bar without a ground-truth label to calibrate against?

Because there is no labelled correctness signal in this domain, none of these can be answered by measuring accuracy. Each had to be answered by a purpose-built, label-free experiment — which is what the bulk of this project consisted of.

03 · System architecture

The six-stage pipeline

Every question flows through generation, blind dual evaluation, three-way corroboration, and a confidence gate. A per-question coin flip decides answer order before either evaluator sees the pair, so neither position nor brand identity can leak into a score.

The confidence score is a weighted blend of six signals. The judge's rubric total carries the most weight, but never a majority — the design deliberately spreads trust across independent sources so no single evaluator dominates:

0.40judge 0.15similarity 0.15wikipedia 0.10model agreement 0.10verifier–judge agreement 0.10wikidata

Any signal that is unavailable for a given question (e.g. no relevant Wikipedia article) has its weight redistributed across the rest, so the score stays valid rather than penalising the answer for a missing external source.

04 · Methodology

Evidence over intuition, at every fork

The defining discipline of the project: no component was adopted, and no parameter set, until a label-free experiment justified it — and results were re-checked whenever a measurement looked too clean to trust.

With no correctness labels, two families of label-free objective were used throughout:

  • Discrimination. A usable evaluator must score a deliberately broken answer far below a solid one. This single test repeatedly separated genuinely useful models from ones that merely produced plausible numbers.
  • Internal consistency & regeneration validity. Signals should predict one another (a weighting where they don't is capturing noise), and a confidence threshold should trigger a retry mainly when a second attempt genuinely improves the answer.

Crucially, the same rigour was turned inward. Three separate times, an analysis produced a striking result that turned out to be a measurement bug — a model's own arithmetic error, a signal secretly derived from the thing it was being correlated against, and a sampling scheme that under-counted part of the data. In every case the error was caught and corrected before the result was reported as a finding, not after. That self-correction record is itself part of the methodology.

Design rule enforced throughout: whenever the judge model or scoring standard changed, the dataset was restarted from scratch. Mixing two labelling regimes in one dataset — a mistake made early and never repeated — teaches any downstream analysis to average two disagreeing standards. The final 5,000 questions are all under one regime.
05 · Key findings & results

Five results that shaped the system

Each was a decision point backed by a real, dated experiment. Presented here in the order the system was hardened.

1

Judge selection: check per-criterion variance, not just averages

Three judge models were trialled. The decisive test was not their average score but whether they discriminated between the eight rubric criteria. CompassJudger-1 looked competitive on totals, yet on a majority of answers it gave all eight criteria the identical score — a flat guess dressed as analysis. qwen3.5:9b never did this.

2

The judge was silently copying the verifier

A routine check found that on 32 of 37 questions, the judge's eight scores matched the verifier's exactly, digit for digit. The judge's prompt was being handed the verifier's numbers as "context," and at low temperature it reproduced them instead of forming an independent view — meaning the "two independent evaluators agree" signal was measuring copying, not agreement. Fixed by scoring the judge fully blind, with no verifier output in its prompt.

Judge and verifier now score independently — agreement became a real signal
3

Position and identity bias was baked into the whole dataset

Until identified, LLaMA 3 was always presented as "Answer 1" and the prompts explicitly named which brand wrote each answer. Position and identity were confounded in the same direction for every question ever generated. The fix was four-layered: strip all brand labels from prompts, randomise answer order per question by coin flip, record true model identity in new columns, and mirror the same randomisation in the live demo.

4

The confidence threshold, proven three ways

The retry threshold could not be calibrated on ordinary data — a second attempt is only ever generated below the threshold, so the data above it is censored. A control group was introduced (a small random fraction of already-passing answers get a second attempt purely for measurement), which supplied unbiased data across the whole score range. Three independent methods then converged:

5

Is the Mistral edge real? An honest, still-open answer

The judge rates Mistral's answers higher specifically on factual correctness, faithfulness, and hallucination-freedom. But the independent verifier, scoring the same pairs, shows no gap on any criterion. A discrimination test confirmed the verifier is not simply blind — it scored a solid answer 77–80/80 against a deliberately broken one at 0–8/80 (average gap 74.5). So its flat reading is a genuine "no measurable difference," which shifts the balance of evidence toward the judge's preference being a model-specific perception rather than a true quality gap.

Reported as an open question, with the evidence for both readings laid out — not forced to a conclusion
06 · Limitations

What this project does not claim

Stated plainly, because a defensible project is precise about the edges of its evidence.

  • No ground-truth accuracy. Every result is internal/label-free by necessity. The system measures self-consistency and corroboration, not verified correctness against an external answer key.
  • The Mistral preference is unresolved. Whether it reflects real quality or a judge artefact cannot be settled without per-answer fact-checking that does not exist at this scale.
  • The verifier (phi3) was never swapped. It clusters near the score ceiling on ordinary answers; it discriminates broken answers well, but it has not been held to the same model-comparison scrutiny the judge received.
  • External fact-checks are partial by design. Wikipedia matched 54% of questions and Wikidata 41% — the relevance gate correctly abstains when no genuinely related source exists, rather than injecting noise.
  • Generalisation is untested. Findings are specific to this model set, this rubric, and this question bank; they are not claimed to transfer unchanged to other models or domains.
07 · Contributions

Why the work stands up

The deliverable is not merely "a pipeline that runs." It is a demonstrated, repeatable method for building and defending an evaluation system where no ground truth exists:

  • A label-free validation protocol — discrimination tests plus internal-consistency and regeneration-validity objectives — that made every model and parameter choice falsifiable.
  • A bias-control design (blind, order-randomised, identity-tracked evaluation) that separates genuine quality signal from position and brand artefacts, and quantifies each.
  • A statistically calibrated confidence gate, with the censored-data problem solved by a purpose-built control group rather than assumed away.
  • A fully instrumented 5,000-question dataset storing every raw signal for every attempt, so any future weighting or threshold can be re-derived without regenerating data.
  • A transparent record of three self-caught measurement errors, each corrected before it became a claim — the strongest evidence that the reported results are trustworthy.
08 · Future work & the open scope decision

Where this can go next

Data collection is complete. The remaining direction is a genuine choice about the project's scope, laid out here for a decision.

The scope question: is the 5,000-question dataset the final deliverable, or the raw material for a next phase? The pipeline and dataset stand on their own as a complete FYP. But the same data could seed a follow-on: training or fine-tuning a lightweight "confidence predictor" that reproduces the six-signal judgment in one cheap pass, or distilling the multi-model ensemble into a single model. That is a scope expansion, not a gap in the current work.

Independently of that decision, three concrete threads remain open:

  • Hold the verifier to the same scrutiny as the judge — run the full model-comparison it never received, given its near-ceiling clustering on ordinary answers.
  • Resolve the Mistral question with a per-answer external fact-check on a sampled subset, the one piece of ground truth that would settle it.
  • Calibrate the RAG relevance gate — retrieval logging is now in place, so with real usage the 0.35 cutoff can be swept the same way the confidence threshold was.
